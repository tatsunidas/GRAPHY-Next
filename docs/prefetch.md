# 事前取得（予約一覧から過去検査を取り込む）

診察の前日・当日に、予約一覧の患者の過去検査を PACS から取り込んでおく機能です。診察室の PC（ネットワークは院内のみ・インターネット接続なし）で、診察の始まりに画像を待たずに開けるようにします。デスクトップ版（standalone）で使えます。

予約一覧は、次のどちらからでも読めます。

- **DICOM MWL（モダリティワークリスト）**: RIS などの MWL サーバーに C-FIND で問い合わせます。
- **RIS の CSV ファイル**: RIS が書き出す予約の CSV を、フォルダの中から読みます。

取得した検査は、**予約日の終わりまで**自動削除の対象から外れます（予約日を過ぎると、通常の保持期間の条件に従います）。

## 設定

**環境設定**{.ui} ▸ **事前取得**{.ui} で設定します。既定値はありません（施設の運用で決まるため）。必須の項目が空のまま有効にすると、保存できず、足りない項目が表示されます。

### 予約一覧

- **予約一覧の元**{.ui}: MWL か CSV を選びます。
- MWL を選んだときは、MWL サーバーを「DICOM 通信先」に登録した AE から選びます。ステーション AE とモダリティは、空なら絞りません。
- CSV を選んだときは、フォルダ・文字コード（UTF-8 か Shift_JIS）・患者 ID の列名・予約日の列名を指定します。
    - フォルダの中で最後に更新された `.csv` を読みます。1 行目は列名です。
    - 予約日の列名が空なら、そのファイルの全行を対象日の予約として扱います。予約日は `YYYYMMDD`・`YYYY/MM/DD`・`YYYY-MM-DD` を読めます。
    - 列名が見つからない、患者 ID や日付が読めない行がある、文字コードが合わない、のいずれかのときは、**何も取得せず**、理由を実行の記録に残します（一部の行だけを取って黙って欠けることはありません）。

CSV の例（文字コード UTF-8、患者 ID の列名 `患者ID`、予約日の列名 `予約日`）:

```
予約日,患者ID,氏名
2026/11/10,P0001,山田
2026/11/10,P0002,鈴木
```

### いつ取得するか

- 対象の日: 当日・翌日・両方から選びます。
- 実行する時刻: `07:00, 18:00` のように、カンマか空白で区切って指定します。
- 「アプリを閉じていて時刻を過ぎていた場合、起動後にその日の分を取り戻す」をオンにすると、起動した時点で、過ぎた直近の時刻の分を実行します（オフのときは、時刻から 5 分以内に動いていた場合だけ実行します）。
- 通信先の障害で途中になった実行は、15 分ごとに再試行します。取得済みの検査は飛ばすので、重複しません。

### 取得の条件

- **取得元 PACS**{.ui}: 「DICOM 通信先」に登録した AE から選びます。
- **取得の方式**{.ui}: C-MOVE か C-GET。C-MOVE は、PACS 側に、このアプリの AE（受信口）を移動先として登録しておく必要があります。登録できないときは C-GET を選びます。
- 遡る年数・モダリティ・患者ごとの件数: いずれも空なら絞りません。件数は新しい検査から数えます。PACS がモダリティを返さないときは、シリーズの一覧から補います。
- 1 検査の待ち時間: 大きな検査を取るときは長めにします。

## 実行と確認

- **予約一覧を確認**{.ui}: 予約一覧だけを取って、日ごとの患者数を表示します。画像は取得しません。
- **今すぐ実行**{.ui}: すぐに 1 回実行します。結果は状態の欄と、**実行の記録**{.ui}に出ます。
- 確認と実行は、**保存した設定**で動きます。入力を変えたら、先に **保存**{.ui} してください。
- 実行の記録には、日時・対象の日・結果・患者数・取得・取得済み・失敗・未処理が残ります。患者名や患者 ID は記録しません。
- 結果の「中断」は、PACS に問い合わせられなかったことを表します。残りの患者は**未処理**として数え、次の再試行で取得します（捨てません）。

取得した検査は、メイン画面の一覧を**更新**すると表示されます（受信したときに一覧が自動では更新されません）。

## 常駐（窓を閉じても動かし続ける）

事前取得は、アプリが起動している間だけ動きます。夜間や早朝に動かすには、**常駐**{.ui}の設定をオンにします。

- **窓を閉じても、タスクトレイに残して動かし続ける**{.ui}: 窓を閉じても、アプリは終わらず、タスクトレイに残ります（受信と事前取得が止まりません）。アイコンのメニューの［開く］で窓が戻り、［終了］で終わります。アプリの更新や OS の終了では、隠さずに終わります。
- **Windows にログインしたら自動で起動する**{.ui}: インストールした版の Windows・macOS でだけ設定できます。トレイに残す設定がオンのときは、窓を出さずに起動します（オフのときは窓を出して起動します）。
- どちらも既定はオフです。オフのときは、今までどおり、窓を閉じるとアプリも終わります。
- 診察室の PC の電源を夜に切る運用では、常駐では間に合いません。起動後に取り戻す設定を併用してください。

## 自動削除との関係

- 取得した検査には、予約日の翌日 0 時までの保護が付き、自動削除（日数・容量・空き容量のどの条件でも）の対象になりません。期限を過ぎると、通常の条件に従います。
- 保持期間（日数）は、「最後の受信から」数えます。事前取得した日から数えるので、3 日などの短い保持期間でも、予約日までは残ります。

## 注意

- 患者 ID の**完全一致**で PACS を検索します。同じ患者に別の ID が振られている場合は、その ID の検査は取得されません。
- 診察室の PC のローカルの DB と、CSV を置くフォルダには、患者情報が残ります。OS のアカウント・画面ロック・フォルダの権限を確かめてください。
- 取得したデータは、DICOM 通信（院内）だけを通ります。インターネットには出ません。
