DICOM 通信と接続の設定ガイド

SCU / SCP の立場ごとに、STORE・QR（FIND・GET・MOVE）で「どちらに何を設定するか」。GRAPHY-Next（スタンドアロン）をサーバーとして使う場合を含む。
作成: 2026-11-16 ／ Visionary Imaging Services
この資料の要点
  • 接続（TCP）を始める側が SCU、待ち受ける側が SCP。設定は「待ち受ける側＝ポートと許可」、「始める側＝相手の宛先」と分けて考える。
  • C-GET: 接続は 1 本だけ。受け取る側（SCU）が相手の AE・IP・ポートを持てば足りる。受け取る側の待ち受けポートは不要。
  • C-MOVE: 接続は 2 本。要求を受けた SCP が、移動先 AE の名前から宛先（IP・ポート）を自分の登録表で引き、新しく C-STORE の接続を張る。移動先の登録と、移動先の待ち受けが要る。
  • Q/R の許可（SOP クラス）が無いと、エコーが通っても QR だけ失敗する。

1. 用語

用語意味
SCU（Service Class User）サービスを使う側。TCP 接続を開始する側（クライアント）。
SCP（Service Class Provider）サービスを提供する側。指定ポートで待ち受ける側（サーバー）。
AE タイトルDICOM ノードの名前（最大 16 文字）。接続のとき、Calling AE（自分の名前）と Called AE（相手の名前）を名乗る。
IP・ポートSCP の待ち受け先。SCU 側の送信元ポートは接続のたびに変わる一時ポートで、設定しない。
SOP クラス「何ができるか」の種類（画像保存、検索、取得など）。接続の交渉で SCU が提案し、SCP が受理・拒否する。
DIMSEC-ECHO、C-STORE、C-FIND、C-GET、C-MOVE などの命令。

2. 操作ごとの早見表

「始める側」＝ SCU（接続を開く）、「待ち受ける側」＝ SCP。画像の向きは操作ごとに違う点に注意。

図 1　C-GET と C-MOVE の接続の違い

GET では、送信側にしか AE・IP・ポートの設定は要らないのか

「GET の要求を出す側（画像を受け取る側）」には、相手（画像の持ち主）の AE・IP・ポートと自分の AE があれば足ります。受け取る側は、待ち受けポートの開放や、自分の IP・ポートを相手に教える必要はありません。画像が、要求したのと同じ接続で返ってくるためです。

一方、画像の持ち主（SCP）側には、次が要ります。

  • GET を含む Q/R の SOP クラスを受理する設定。
  • 要求元の AE タイトルの許可（製品によっては IP も）。ここが抜けると、エコーが通っても GET・FIND・MOVE が拒否される。

注意: C-GET に対応しない PACS は少なくありません。その場合は C-MOVE を使います。

3. GRAPHY-Next（スタンドアロン）の設定

以下は、GRAPHY-Next の実装（main、2026-11-16 時点）の確認に基づきます。画面の名称は環境設定内の表示です。

3.1 GRAPHY-Next 自身の「ノードとしての設定」

項目内容
自局 AE タイトル既定は GRAPHYNEXT。SCU として接続するときの Calling AE、SCP として待ち受けるときの AE 名になる。
SCP リスナー既定は無効。有効にすると、既定ポート 11112、バインドは全 NIC（0.0.0.0）で待ち受ける。
TLS使う場合は平文とは別のポート（既定 2762）で待ち受ける。既定で相互 TLS（クライアント証明書を要求）。
通信先（リモート AE）環境設定の「DICOM 通信先」に、相手の AE タイトル・ホスト・ポート・TLS の有無を登録する。送信・検索・取得・移動の宛先になり、C-MOVE の移動先の表としても使う。
保存先受信した DICOM は、ローカル保管庫（既定 ./data/dicom）に保存する。

3.2 GRAPHY-Next を SCP（サーバー）として使うとき

受ける操作既定の挙動と、必要な設定
C-ECHO常に応答する（SCP が起動していれば）。
C-STORE（受信）SCP を有効にし、ポートを開放すれば受信できる。実装上、呼び出し AE の許可リストは設けていない（受信側 AE に絞り込みを設定していない）。
C-FIND / C-GET / C-MOVE（他端末からの検索・取得）患者情報を返すため、既定は OFF。環境設定の「他端末からの検索を受け付ける」を ON にする（SCP の起動時に読むので、変更後は再起動）。
Q/R を許可する相手ON にしても、既定では登録済みの通信先 AE（AE タイトルが一致するもの）からの要求だけに応える。登録外の相手に応えるには「登録外にも応える（すべて許可）」を設定する。許可の判定は要求のたびに行うので、通信先の追加・変更はすぐに効く。
C-MOVE の宛先宛先 AE は、「すべて許可」にしても登録済みの通信先だけ。未登録の宛先は失敗（0xA801）、許可されない相手は 0xC000。TLS が要る宛先で TLS が使えないときは、平文で送らず 0xA702 で失敗にする。
呼び出し AE タイトルは相手の自己申告で、偽装できます。本人確認が必要な環境では、相互 TLS（クライアント証明書）を併用してください。

3.3 GRAPHY-Next を SCU（クライアント）として使うとき

操作GRAPHY-Next 側相手（PACS・モダリティ）側
送信（C-STORE）通信先に相手の AE・ホスト・ポートを登録。待ち受け・Storage の受理。製品によっては GRAPHY-Next の AE（と IP）を登録。
検索（C-FIND）通信先を登録。「通信テスト」で、通る検索方式を調べて採用できる。GRAPHY-Next の AE に、Q/R（FIND）を許可。
取得（C-GET）通信先の登録だけ。待ち受けは不要。GRAPHY-Next の AE に、GET を含む Q/R を許可。
取得（C-MOVE）通信先を登録。SCP を有効にして、ポートを開放（移動先＝自局 AE として受信する）。GRAPHY-Next を移動先 AE として登録（AE・IP・ポート）。MOVE を許可。

3.4 場面別のチェック（スタンドアロンをサーバーに使う）

場面GRAPHY-Next 側相手側

4. ファイアウォールとネットワーク

  • 開放するのは、待ち受ける側のポートだけ（受信側の入口）。SCU 側の送信元ポート（接続のたびに変わる一時ポート）の設定や開放は不要。
  • C-MOVE では、移動先ノードの待ち受けポートも、持ち主側から到達できる必要がある（NAT・VPN をまたぐ構成で詰まりやすい）。
  • 相手のサーバーが複数の AE を持つ場合、Called AE ごとに許可する操作（Q/R の可否）が違うことがある（例: 受信専用の AE と、検索用の AE）。

5. エラーの切り分け

症状（ログの文言）主な原因と確認先
接続できない／タイムアウトIP・ポート違い、ファイアウォール、相手が起動していない。
A-ASSOCIATE-RJ（Called AE が不明など）Called AE の名前違い（大文字小文字・末尾の空白も）。相手側の AE 登録。
A-ASSOCIATE-RJ（Calling AE が不明など）相手に自分の AE が登録されていない。
エコーは通るが QR が失敗
abstract-syntax-not-supported (provider rejection)		Q/R の SOP クラスが、その AE に許可されていない。情報モデル（Patient Root / Study Root）や検索キーを変えても直らない。相手の管理者に、自局 AE への FIND・GET・MOVE の許可を依頼する。Q/R 用の別 AE が無いかも確認。
EOFException（接続確立後に切断）上の拒否の副作用のことがある（拒否の後に要求を送り、相手が切る）。ログの result: 3 の有無を先に見る。無ければ、相手の処理失敗（返却キーが重い・非対応）を疑う。
C-MOVE で「移動先が不明」（0xA801）要求を受けた側に、移動先 AE が登録されていない。
C-MOVE は成功と出るが、画像が届かない移動先の待ち受け（ポート・FW）、または移動先の登録 IP・ポートの間違い。
0xC000（許可されない）要求元 AE が、相手の許可リストに無い。

6. 設定の前に確認するチェックリスト

  1. どちらが接続を始めるか（SCU）、どちらが待ち受けるか（SCP）を決める。
  2. SCU: 相手の AE・IP・ポートと、自分の AE を確認する。
  3. SCP: 待ち受けポート、自分の AE、受理する SOP クラス（Storage / Q/R）、許可する相手の AEを確認する。
  4. C-GET: 画像を受け取る側の待ち受けは不要。持ち主側の GET 許可を確認する。
  5. C-MOVE: 持ち主側に移動先 AE の AE・IP・ポートを登録し、移動先の待ち受けを確認する。
  6. ファイアウォールは、待ち受け側（と C-MOVE の移動先）のポートを開ける。
  7. まず C-ECHO、次に C-FIND、最後に GET/MOVE の順で確認する。

本書の「製品別の設定画面」には触れていません（相手の製品により異なるため）。GRAPHY-Next 以外の記述は、DICOM の一般的な仕組みに基づく一般論です。
