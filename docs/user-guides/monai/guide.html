05 / DICOM SEG とは

SEG は「どの画素が、どの臓器か」の記録です

元の CT シリーズ

  • 画像そのもの（患者・検査・スライスの位置）
  • 変更されません
＋

SEG（新しいシリーズ）

  • 臓器ごとの塗り（セグメント）。1 臓器 ＝ 1 セグメント。名前（例: spleen）と色がつきます
  • 各スライスの位置・向き（患者座標・mm）を持ち、元の画像の格子に合います
  • 元のシリーズへの参照。患者・検査の情報は元のシリーズから引き継ぎます
  • 画像は含みません。塗りの 0/1 だけです（BINARY 形式）

  • ラベル番号と臓器名の対応は、モデルごとに違います。保存された SEG には、臓器名がセグメント名として入ります。

  • 前景が無い（何も塗られなかった）ラベルは、保存されません。保存の確認画面に、セグメント数が出ます。

  • SEG は DICOM の標準の形式です。元のシリーズと一緒に開けるビューアで、塗りを重ねて見られます。

  • 結果は研究用です。SEG に保存しても、診断に使える結果になるわけではありません。

  • SEG の中の「アルゴリズムの種類」は、すべて MANUAL と書かれます（本体の既定）。AI が作ったことは、シリーズ説明の [Plugin] で見分けてください。

研究用です。診断には使わないでください。10 / 13

06 / 困ったとき・既知の制限

うまくいかないときと、いまわかっている限界

うまくいかないとき

出たこと対処
足りないものの表が出た表の pip install をターミナルで実行 → 「再確認」
Bundle が追加のパッケージを求めた枠に出た名前を、同じ Python に入れて、もう一度「実行」
Jupyter などを後から入れたのに「local-unavailable」GRAPHY を再起動（次の版で直す予定です）
Colab で GPU の空きが無い／利用枠を使い切った時間をおく、別の種類を選ぶ
GPU のメモリ不足（CUDA out of memory）軽いモデルにする。設定値で解像度を下げられるモデルもあります
署名つきで入れたプラグインを zip で入れ直せない本体の次の版から、zip と同名の .minisig も一緒に選びます。0.5.1 では、いったん削除してから入れます

いまわかっている限界（実機の検証）

  • 脾臓（10 例・独立データ）: Dice の平均 0.858（最小 0.536、最大 0.949）。10 例すべてで、予測の体積が基準より小さい傾向1 例は脾臓の一部しか拾えませんでした。原因は未確認

  • 全身 104 臓器（wholeBody）: 既定の設定では、T4 で10 例すべて失敗。確認できた原因は、メモリ不足の 1 例だけです低解像度の設定では 7 例が完走。結果はばらつきます

  • 向き・体積の検証は、一部のモデルだけです。ほかのモデルは、必ず画像で確かめてください

研究用です。診断には使わないでください。出典: docs/monai-verification.md（AMOS22 の CT 10 例・Colab T4）。Windows の自前 Jupyter は未確認です。13 / 13
