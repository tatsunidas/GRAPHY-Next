# 外部から検査を開く（RIS 連携）

RIS などの別のソフトから、読影室の同じ PC にある GRAPHY-Next に「この検査を開く」と頼めます。ネットワークは待ち受けません（LAN から呼び出せる口は作っていません）。デスクトップ版（standalone）で使えます。

## 呼び方

次のどちらかで、検査を指定して GRAPHY-Next を起動します。アプリがすでに動いていれば、そのウィンドウに渡して 2D ビューアが開きます（2 つ目のアプリは立ち上がりません）。動いていなければ、起動してから開きます。

### カスタム URL

```
graphynext://open?studyInstanceUid=<検査 UID>
graphynext://open?studyInstanceUid=<検査 UID>&seriesInstanceUid=<シリーズ UID>
graphynext://open?patientId=<患者 ID>&studyDate=<YYYYMMDD>
```

OS から URL を開く方法（Windows は `start`、macOS は `open`、Linux は `xdg-open`）で呼べます。インストーラで入れた版が、OS に `graphynext://` を登録します（開発版は登録しません）。

### コマンドライン引数

```
GRAPHY-Next.exe --open-study=<検査 UID>
GRAPHY-Next.exe --open-study=<検査 UID> --open-series=<シリーズ UID>
```

RIS が URL を扱えず、実行ファイルを呼ぶ場合に使います。**値は `=` でつないでください**（`--open-study <UID>` のように空白で分けると、値を取り違えるため、開きません）。

## 指定のきまり

- 検査 UID・シリーズ UID は、数字とドットだけで 64 文字までです。患者 ID は 64 文字までで、制御文字は使えません。検査日は実在する `YYYYMMDD` です。
- 患者 ID と検査日で指定したとき、同じ条件の検査が **1 件**に絞れたときだけ、そのまま開きます。複数あるときは一覧を出して選んでもらいます（黙って先頭を開きません）。患者 ID は完全に一致したものだけを対象にします。
- 検査が見つからないとき、シリーズ UID が見つからないとき、指定の形式が正しくないときは、理由を出して何も開きません。
- 値はパスやコマンドとして使われません。`..`・`;`・`|` などを含む値は形式の違反として断ります。

## 設定

環境設定 ▸ DICOM通信 ▸「外部から検査を開く（RIS 連携）」:

- **外部から検査を開く要求を受け付ける**（既定オン）。オフにすると、要求が来ても開かず、その旨を表示します。
- **外部から開く前に確認する**（既定オフ）。オンにすると、患者名と検査日を出して、承諾してから開きます。Web ページのリンクなどで意図しない検査を開かされるのを避けたいときに使います。

## 作っていないもの・注意

- XML-RPC など、LAN から呼べる「検査を開く」命令口は作っていません。認証の無い口が院内に露出するためです。そのような口を前提に作られた連携モジュールは、そのままでは使えません。
- どうしてもネットワーク越しに呼びたいときは、利用者の責任で、認証をかけたリバースプロキシや、同じ PC 上の小さな中継ソフトを置いて、上の URL またはコマンドを呼ぶ形にしてください。
- `graphynext://` のリンクを踏むと、すでに保管庫にある検査が画面に出ます（データが外に出るわけではありません）。気になる環境では、上の「開く前に確認する」をオンにしてください。
- パッケージ版は、同じ PC で GRAPHY-Next を 2 つ起動できなくなります（2 つ目の起動は、先のアプリへ要求を渡して終わります）。
