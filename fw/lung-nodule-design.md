# CT 肺結節の検出（研究版）設計

> 記録開始 2026-10-06。開発計画（Documents/GRAPHY-Next_開発計画_2026-10.pdf）では「激戦（富士フイルム・プラスマンなど）・避ける」としていたが、
> 2026-10-05 にユーザが TODO に加えた（`fw/ct-quant-design.md` §9）。**研究用（非医療機器）**。良悪性・Lung-RADS・Fleischner の分類や経過観察の推奨は出さない。

## 0. 要約

- 公式プラグイン **`vis-lung-nodule`（「CT 肺結節」）**。`category: "ai"` で「解析 ＞ AI」に 1 項目。
- モデルは **TotalSegmentator の `lung_nodules` タスク**（v2.18.0 に同梱・Apache-2.0）。同じジョブで `total` も走らせ、肺葉で場所を出す。
- 結節は「`lung_nodules` の前景の連結成分」1 つ = 1 個。成分に分けるのは計算機の上（後処理）。**数値は本体が測る**（体積・CT 値は H66、3 方向の径は H33）。
- 一覧（場所・体積・体積から出した径・3D の径・平均 CT 値）→ クリックでそのスライスへ。SEG（結節ごとのセグメント）・SR・CSV で保存。

## 1. モデルの選定（2026-10-06 に原典で確認）

| 候補 | 出力 | ライセンス | 判断 |
|---|---|---|---|
| **TotalSegmentator `lung_nodules`** | ラベル（lung・lung_nodules） | Apache-2.0（README の「Openly available for any usage」・v2.18.0 のタグで確認）。BLUEMIND AI 提供・1353 例で学習（一部 LIDC-IDRI） | **採用**。マスクなので体積・径を本体で測れる。CT 定量と同じパッケージ・版（2.18.0）で動く |
| MONAI `lung_nodule_ct_detection` 0.6.10 | 検出枠（Nx6）とスコア | コード Apache-2.0。学習データは LUNA16（CC BY 4.0）・LIDC-IDRI（CC BY 3.0）。metadata の intended_use は "This is an example, not to be used for diagnostic purposes" | 見送り。枠しか出ないので体積が測れない。vis-monai はセグメンテーションしか扱わない |

- `lung_nodules` は 1 つのラベル（全結節で同じ値）。個々の結節は連結成分で分ける。
- 出典: https://github.com/wasserth/TotalSegmentator/blob/v2.18.0/README.md 、`totalsegmentator/map_to_binary.py`（`"lung_nodules": {1: "lung", 2: "lung_nodules"}`）、https://huggingface.co/MONAI/lung_nodule_ct_detection
- ⚠ v2.18.0 の README では `vertebrae_body` も「Openly available」側にある。`resources/improvements_in_v2.md` は「非商用のみ」と書いていて食い違う（CT 定量の §4.4 は後者を採っている。ユーザに報告して扱いを決める）。

## 2. 計算機の上（vis-ct-quant の実行部を写す）

1. npz → NIfTI（vis-ct-quant と同じ）。CT 以外・GPU なしは止める。
2. `totalsegmentator(task='lung_nodules', ml=True)` と `totalsegmentator(task='total', ml=True, roi_subset=肺葉 5 つ)`。
3. 結節の前景を **26 近傍の連結成分**に分ける（`scipy.ndimage.label`。TotalSegmentator の依存に入っている）。成分の番号を 1..N にし、肺葉のラベルと合わせて 1 本のラベルの volume にする（結節 = 1..N、肺葉 = 1000 番台 → uint16）。
4. 成分のボクセル数・各成分がいちばん多く重なる肺葉は結果の JSON に入れる（**数値の表示には使わない**。本体の H66 と突き合わせて経路を確かめるため）。

連結成分の近傍は 26 にする（斜めにつながったボクセルも 1 つの結節。6 近傍だと細い結節が割れる）。大きさで捨てる閾値は置かない（全部出して体積の順に並べる。1 ボクセルの成分も「1 ボクセル」と見えるように出す）。

## 3. 本体で測るもの

| 量 | どう出すか |
|---|---|
| 体積（mL） | H66（数え上げ） |
| 体積から出した径（mm） | 同じ体積の球の直径 d = (6V/π)^(1/3)。H66 の体積から計算するだけ |
| 3D の径（長・中・短、mm） | H33 `measureMask`（PCA 軸への投影の範囲）。結節ごとにメッシュを作るので、成分が多いときは上位だけにする（数は画面で選ぶ） |
| 平均 CT 値・SD | H66 |
| 場所 | 肺葉（その結節と重なるボクセルがいちばん多い肺葉）。重心（LPS mm） |

- **アキシャル面の長径・短径（RECIST・Fleischner の測り方）は v1 では出さない**。3D の PCA の径とは別の量で、取り違えると臨床の基準と比べてしまう。名前で区別し、SR の `longAxis`・`shortAxis`（SRT の標準コード）には入れない。
- 充実性・部分充実性・すりガラスの分類はしない（平均 CT 値は出すが判定しない）。

## 4. 画面

- 対象シリーズ・研究用の注意・実行。
- 結節の一覧（体積の順）: 番号・肺葉・体積・体積から出した径・3D の長径・平均 CT 値・ボクセル数。行を押すとその結節の重心のスライスへ（`goTo`）。**`goTo` のスライス番号と H10 の k の並びが同じかは N1 で確かめる**。
- ROI マネージャへ読み込み（H65。結節ごとに「nodule 1 (RUL)」のような名前）。
- 保存: SEG（結節ごと＋肺葉は入れない）・SR（結節ごとのグループに volume・meanValue、径は所見の文に書く）・CSV。

## 5. 検証

| 何を | どう | 合格の基準 |
|---|---|---|
| 連結成分と本体の計測 | 既知の半径の球（と、斜めにだけつながった 2 個組）を置いた合成 CT のラベルで、成分の数・体積・径を真値と比べる | 成分の数が一致、体積は数え上げで一致、体積から出した径は解析値と一致 |
| 経路（向き・格子） | 計算機が数えた成分ごとのボクセル数と H66 の数が一致。肺葉の左右（LPS の x） | 全成分で一致・取り違えなし |
| 実機 | 結節のある胸部 CT を Colab で通す（データは下） | 実行・一覧・goTo・保存が通る。重ね表示はスクリーンショットで判定 |
| モデルの精度（参考値） | **学習に使われていない**公開データで、結節ごとの検出（感度・偽陽性/例）と体積の誤差 | 合否ではなく数値を残す |

- 実機用の胸部 CT: LIDC-IDRI（TCIA・CC BY 3.0）から 1 例。`lung_nodules` の学習に一部使われているので**精度の評価には使わない**（動作の確認だけ）。
- 精度の参考値に使う公開データの候補は §9（2026-10-06 調査）。

## 8. 実機の結果（2026-10-06・N2）

`automator/src/spike/computeLungNoduleCheck.ts` **17/0**（Colab T4・LIDC-IDRI-0001 の CT 133 枚＋読影医の SEG 1 つ。TCIA・CC BY 3.0。データは `.results/lidc-0001` に NBIA の getImage で取得・git には入れない）。

- 2 タスクで 231 秒・GPU 最大 3016 MiB。候補 1 個（左下葉・5.522 mL・体積から出した径 21.9 mm・3D の径 23.9 / 23.4 / 22.8 mm・平均 −6.1 HU）。
- 計算機が数えた成分のボクセル数 = H66 = H33（切り出したマスク）で一致。
- 読影医の結節（SEG・7.298 mL・等価半径 12.0 mm）の重心から、候補の重心まで 1.1 mm。体積の差は読影医 1 人ぶんとの比較で、精度の評価ではない（LIDC-IDRI は学習に一部使われている）。
- 一覧の行を押すと、重心のスライス（スタックの 90・画面表示は Z 91/133）へ移動し、左下葉の背側に結節が重なって出ることをスクリーンショットで確認した。
- SEG は結節だけ（肺葉は入らない）。SR は体積・平均 CT 値で、標準の長径コード（G-A185）は使っていない。

合成 CT での照合（§5 の 1 行目）は、成分分けを node --test の偽 TotalSegmentator（26 近傍で 3 個）で、本体の数え上げを `fw/ct-quant-design.md` §7.1 の合成 CT（H66・23/0）で確かめた。**H33 の 3D の径を球の真値と比べる照合はしていない**（H33 は既存の検証済みの実装で、今回は変えていない）。

### 9.1 NLSTseg での途中結果（2026-10-06・5 例）

- 症例は Image.xlsx の並びの先頭から 10 例（`automator/scripts/fetch-nlstseg-cases.py`・Range で 441 MB）。Colab T4 で `automator/src/spike/computeLungNodulePublicCheck.ts` を流したが、**この PC の C ドライブが満杯（空き 0）になり、1 例（100242）が空き不足で失敗、残り 4 例は中断した**。照合できたのは 5 例。
- 照合（`automator/scripts/eval-lung-nodule-public.py`）: 病変はデータセットの定義（マスクの値＝Label.xlsx の Mark_labels）で数える。最初に連結成分で数えたら、100012 の病変が 0.00・0.01 mL の切れ端で 3 個に割れたので改めた。

| 症例 | 正解の病変 mL（等価径 mm） | 検出 | Dice | 候補の体積 mL | 体積の誤差 % | 注釈の外の候補 |
|---|---|---|---|---|---|---|
| 100012 | 5.84（22.3） | あり | 0.286 | 0.98 | −83.2 | 1 |
| 100147 | 4.80（20.9） | あり | 0.019 | 0.05 | −99.0 | 1 |
| 100158 | 1.02（12.5） | あり | 0.773 | 0.66 | −35.0 | 0 |
| 100280 | 1.21（13.2） | あり | 0.336 | 0.25 | −79.3 | 1 |

- 検出 4/5、検出した病変の Dice の中央値 0.311、体積の誤差の絶対値の中央値 81%（**どれも小さく出る**）。
- 経路の確認: 正解の体積は本体の格子に写した値と NIfTI から出した値が 5 例とも一致、候補と病変は重なっている（位置・向きの取り違えなし）。計算機の数え上げと H66 は全例で一致。
- **小さく出る理由はまだ分からない**（推測で書かない）。切り分けには、同じ NIfTI に TotalSegmentator を直接かけた結果と GRAPHY を通した結果の比較（CT 定量の §7 と同じ「経路の一致」）が要る。NLSTseg の正解は肺癌（12〜30 mm 相当）で、`lung_nodules` が何の大きさの結節を想定して学習したかは公開されていない。
- 残り: 中断した 5 例の再実行（ディスクの空きが要る）、経路の一致の確認。
