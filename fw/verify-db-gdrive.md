## 1. 検証したこと（マイドライブ・共有ドライブ。同じ手順で、保存先だけが違う）

`gdriveInstalledSmoke.ts --mode full --scenario full`（配布物を起動し、backend→Google の経路に中継を挟んで断を注入。Drive 側は別の経路で独立に確認）。

| # | 内容 | 結果 |
|---|---|---|
| 1 | 配布物が起動し、メイン画面が出る | 合格 |
| 2 | HCC_001（110 件）取り込み → ログイン → 有効化 → 初回同期。Drive の件数・md5 がローカルと一致（重複 0・不一致 0） | 合格 |
| 3 | 追加の取り込みが増分で載る（112 件一致） | 合格 |
| 4 | ネット断: 状態が「オフライン」で未送信が残る（Drive 112 < ローカル 114）→ 復帰後に残件が空、114 件一致 | 合格 |
| 5 | ローカルで検査を削除 → Drive ではゴミ箱に 1 件、非ゴミ箱は 113 件で一致 | 合格 |
| 6 | SIGKILL → 再起動で残件が空、114 件一致（重複なし） | 合格 |
| 7 | 正常終了: 終了前にロックが Drive にある → 終了後に解放、新しい索引スナップショットが置かれる（1→2 世代） | 合格 |
| 8 | 別プロファイル（別の PC を模す）でログイン → Picker でバックアップフォルダを選ぶ → 空フォルダへ復元。114 件の md5 一致、索引が復元され、開くと検査 UID 2 件が一致 | 合格 |

最終: 通し **合格 22 / 失敗 0 / 未達 0**、復元 **合格 5 / 失敗 0 / 未達 0**。

- 項目 8 は、通し試験が作ったフォルダ（`…20261015`）ではなく、前日の通し試験が作ったフォルダ（`…20261014`）を選んで復元した（試料は同一）。**通し試験が作ったフォルダそのものからの復元は未確認**（終了時スナップショットが置かれることは項目 7 で確認）。
- 初回同期の所要: 110 件でおよそ 7 分（1 件あたり約 3 秒）。1 回目の実行では 5 分の待ちで 87 件までだった。速度の改善は未着手。

## 2. この検証で見つかり、直したもの

| 問題 | 種別 | 対応 |
|---|---|---|
| バックアップでないフォルダ（親など）を復元元に選ぶと、エラーにならず「完了・0 件」になる | **製品の欠陥** | `not-backup-folder` で失敗にする。backend テスト追加（ガードを外すと落ちることを確認）、ja/en 文言追加 |
| 増分直後に「残 0」と誤判定 / 断の最中に件数一致を要求 / ゴミ箱を一覧に反映される前に確認 / 終了時スナップショットを「1 世代以上ある」だけで見ていた・閉じた直後に次を起動していた | 検査側（スモーク） | 直した。終了時は backend の終了を待ち、終了前にあった世代と比べる |

## 3. 未検証

- 共有ドライブでの、復元元に選んだフォルダの取り違えの有無（同名のフォルダがマイドライブにもあった）。
- 通し試験が作ったフォルダそのものからの復元。
- 翌日以降の refresh token での再発見（保存先フォルダの再発見は別 PC のログインでは確認済み）。
- 別の端末が使用中のときの拒否・引き継ぎ（backend の単体テストと実 Drive テストのみ。画面での確認は未実施）。
- Windows / macOS（Actions の実 OS ランナー）。
- リリースでの OAuth クライアントの同梱（`release.yml` は書き出しと検査を手元で確認。secret `GRAPHY_GDRIVE_OAUTH_CLIENT` の登録後に、リリースで確認する）。

## 4. 手順（人が行う部分）

1. 設定 → データ → 「Google Drive にバックアップ」でログイン（ブラウザで許可）。
2. 「保存先を選んで有効化」で Picker からフォルダを選ぶ（その直下に `GRAPHY-DB-<名前>-<日付>` ができる。マイドライブ・共有ドライブとも可）。
3. 状態が「同期済み」になり、Drive の `dicom/` に件数・md5 が一致して載ることを確かめる。
4. 復元: 設定 → データ →「Drive から復元」→ Picker で **`GRAPHY-DB-…` フォルダそのもの**を選ぶ（親ではない）→ 空のフォルダを選ぶ。
5. 後始末: 検証用の `GRAPHY-DB-…` フォルダは Drive でゴミ箱へ。
