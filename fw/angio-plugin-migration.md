# アンギオ計測のプラグイン外出し — 経緯と、そこから生まれた host API（G1〜G6 / H35〜H39）

> **この文書の出自**: 非公開リポジトリ `graphy-next-plugin-angio-quant`（plugin id `angio-quant`）の
> `docs/host-api-gaps.md` と `README.md` から、**リポジトリを畳むにあたって本体へ移した記録**
> （2026-09-02）。実装は移していない——**計算コアは元から本体にあり、あちらは写しだった**
> （`qlv.ts` / `xaRecon3d.ts` / `xaBifurcation.ts` はバイト単位で同一、`qca.ts` は本体のほうが進んでいた）。
>
> 🔑 **残す理由**: 本体の host API **H35〜H39 が「なぜ生まれたか」はここにしか書かれていない。**
> `fw/plugin-architecture.md` は結果（API の一覧）だけで、**無いと何が起きるか**が落ちている。
> 同種の外出しを次にやるとき、同じ検討を最初からやり直さないための記録。

## 1. 何を外に出し、何を本体に残す判断だったか

| | プラグインが持つ（＝計算） | 本体に残す（＝表示と DICOM） |
| :- | :- | :- |
| 中身 | QCA（中心線・エッジ・密度計測の径・MLD/RVD/%DS/病変長・手修正）／QLV（Area-Length・EF・壁運動）／3D QCA（再構成・バンドル調整・ワーキングアングル）／3D 分岐部 | 2D ビューア・シネ／DSA の合成ローダ／**空間校正**／GSPS・SR・MP4・PNG の書き出し／レポート本体 |
| 判断基準 | **この機能の中身**（何を測るか、どう解釈するか） | **汎用の能力**（他プラグインも使える）と、**単一入口でなければ壊れるもの** |

🔴 **空間校正を本体に残したのは「単一入口」だから**（`fw/angio-design.md` §7.2）。
本体のスケールバーと計測ラベルは metaData プロバイダ経由で描かれるので、
校正を**確定する**口が 2 つあると画面と数値が食い違う。プラグインには**読ませるだけ**にした。

🔴 **DSA の合成ローダも本体**。Cornerstone の image loader を登録する口がプラグインに無い。
そもそも表示の仕事である。

## 2. 足りなかった host API（G1〜G6）と、その帰結

> G 番号は当該リポジトリ内の仮番号。本体の採番は `fw/plugin-architecture.md` §7。

| # | 足りなかったもの | **無いと何が起きるか** | 本体での実装 |
| :- | :- | :- | :- |
| **G1** | 空間校正の**出自・信頼度・警告** | mm/px の数値は取れるが、**それが実測か幾何近似か未校正かが分からない**。「近似には近似と書く」（§7.4）という設計なのに、プラグインが**正しい注記を書けない**＝黙って数値だけ出すことになる | ✅ **H35** `getSpatialCalibration` |
| **G2** | XA 固有の状態（DSA のマスク・シフト・`PixelIntensityRelationship`・フレーム軸） | 差分表示中は血管が**正の大きな値**になる。知らずに非サブトラクションとして測ると**エッジの向きを取り違える**。`profileDomain` も決められない（LOG 保存の装置で二重に対数を取る） | ✅ **H36** `getXaState` |
| **G3** | 任意の計測種別を受ける SR | 旧 H9 は `longAxis` / `shortAxis` だけで**未知の種別は拒否**。MLD・RVD・%DS・病変長・EF・3D 長さがいずれも通らず、**計測値を DICOM に残せない** | ✅ **H37** `saveAngioReport`。H9 を一般化するのではなく、**本体の SR writer をプラグインからも呼べるようにした**（出力が本体と同じ構造・同じコードになる） |
| **G4** | XA GSPS（11.5）の読み書き | DSA のマスク・ピクセルシフト・VOI・空間校正・QCA の描画を残す唯一の器。無いと**解析結果を再現できない** | ✅ **H38** `savePresentationState`（**書きのみ**。適用は表示の仕事なので本体に残す） |
| **G5** | 解析結果をレポートへ差し込む | A14 の登録簿へ積む口が無いと、**出自と限界ごとレポートに載せる**という A14 の要点が失われる | ✅ **H39** `publishAnalysisResult`（`caveats` 必須） |
| **G6** | **ベクター図形のオーバーレイ** | 中心線・エッジを**本体のタイルに重ねて掴んで直す**のに要る。H4a は**値マップ（ラスタ）のみ**なので、線は描けても動かせない | ⬜ **未実装**。回避策あり——本体の `QcaEditor` は Cornerstone に依存しない**素の canvas** なので、同じものをプラグイン窓（H30）の中に作れる |

### 優先順位の考え方（次に同じ検討をするとき）

1. **無いと数値が静かに間違うもの**（G1 / G2）を最優先。エラーが出ないので気付けない
2. **無いと残せないもの**（G3 / G4 / G5）。間違いはしないぶん次
3. **回避策があるもの**（G6）は最後

### 設計上の決めごと

- **G3 / G4 は DICOM を書く口**。本体の方針は「**DICOM はプラグインに書かせない**」（H4b / H9 と同じ）。
  渡すのは**測った内容**だけで、SR の構造・UID 採番・患者/検査属性の継承は本体が行う。
  **プラグインに Part-10 を組ませない。**
- **G1 は「読む」だけ**。校正を**確定する**のは本体に残す（§1 の単一入口）。
- 🔴 **H37 は「開いているタイルの並びに無い SOP」を拒否する。** 書き手は参照インスタンスから
  患者・スタディを継承するので、この検査が無いと**他患者の検査にレポートが生える**。

## 3. 実機でしか出なかったこと

**「host API を足したら、その API を使う検証用プラグインまで書いて実機で回す」**——
本体の画面では何も壊れて見えないのに、プラグイン経路だけで起きた穴が 2 件出ている。

| 症状 | 中身 |
| :- | :- |
| 計測が 0 件に見える | `getRois()` が XA の**幾何なし画像**で世界座標変換に失敗していた |
| 保存経路が丸ごと使えない | XA のフレーム imageId から SOP UID が取れず、H37 / H38 / H39 が全滅 |

🔴 **手書きの型は本体の契約の「写し」で、TypeScript は写し間違いを教えてくれない。**
実機で当てるまで気付けない類いを 2 件踏んだ:

| 間違えたもの | 正しいもの | 症状 |
| :- | :- | :- |
| `openWindow().root` | **`.container`** | `undefined.appendChild` で**プラグインが起動しない** |
| `ViewerRoi.toolName` | **`.tool`** | 計測が 1 件も見つからず、**解析ボタンが押せないまま黙って終わる** |

→ 型の正本は `examples/plugin-template/graphy-plugin.d.ts`。本体側に
「テンプレートが契約に追随しているか」を見るテストがあるので**そちらは古くならない**。
ただし**メンバ名の存在しか検査していない**（型が同一かまでは見ていない）。

| 段 | 内容 | 状態 |
| :- | :- | :- |
| **1** | 計算コアをプラグインへ写す。読み込めるところまで。**本体は無傷** | ✅ 2026-08-25 |

🔴 **「第 5 段までは本体の実装を消さない」**——消してからプラグインが動かないと分かると、
利用者にはただの機能喪失に見える。この原則は守られ、**本体の QCA / QLV / 3D はいまも本体にある**。

### なぜ止まったか（2026-09-02）

段 3（UI 移設）に入る前に、**QVA の責務が `graphy-next-plugin-aneurysm-detector` へ移った**
（`fw/angio-design.md` §9.1）。残る QCA / QLV / 3D は本体で動いており、移行を続ける差し迫った
理由が無かったため、`angio-quant` は畳んだ。**再開するならこの表の段 3 から。**

⚠️ **同期の運用も一緒に消えた。** あちらは `tools/syncCore.mjs` で本体の写しとのずれを
検査していた（`npm run check:sync`）。**再開時は写しを取り直すこと**——畳んだ時点で
`qca.ts` は既に本体のほうが進んでいた（56,605 B ↔ 61,231 B）。

## 5. 配布まわりで効いてくる制約（外出しを再開するなら先に読む）

- **導入操作は desktop 限定**。web は常に 403（運営がイメージに焼き込む形でのみ配備可能）
- **JAR バックエンドは web 不可**（サンドボックス未実装）。フロント面（`ui.js`）は両モード共通
- **`ui.js` は単一ファイル配信必須**（`src/` 分割の相対 import は 404。配布時に 1 ファイルへバンドル）
- **`ui.js` から外部 API は呼べない**（本番 CSP の `connect-src` が localhost 限定）
- **秘匿性は無い**。`ui.js` は素の JavaScript として配信される。アルゴリズムを隠したいなら
  JAR（backend 面）に置くしかないが、**その場合 web では実行できない**（両立しない）
- **プラグインは本体と同じ権限で動く**（`permissions` 宣言は同意画面の表示だけで強制ではない）
